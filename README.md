# 星藏 StarFolio

> 把值得重读的文章与讨论，留在自己的设备。 / Keep articles and discussions worth revisiting on your own device.

[English](README.en.md)

星藏是一款开源、本地优先的网页归档阅读器。链接先加入本机待办，由配置好的 Agent 核对并归档；也可手动导入浏览器保存的页面。保存正文、可见评论、作者与个人资料链接、图片，再用同站点共用的阅读样式重新打开。归档留在本机，不传到组织仓库。

## 能做什么

- Tauri 2 + Rust，桌面支持 macOS / Windows / Linux；项目配置还生成 iOS、Android 工程。
- 论坛讨论尽量读取公开帖子流，记录楼层、帖子 ID、用户 ID、主页、日期、回复楼层与当时能读取到的内容。
- 通用 HTML 正文及可识别评论提取；清除脚本、表单、隐藏内容、广告和常见推广区块。
- 图片按内容哈希去重、验证格式后保存在私人归档；原文仅保留为引用。
- 可编辑的站点级 CSS，只存本机并应用于该站所有归档。
- 浏览器可正常阅读时可导出 `starfolio.discourse-dom.v1` JSON，并在应用中导入。保存为文件须遵守网站使用规则；不绕过登录、验证码或付费墙。
- 命令行：`cargo run --manifest-path src-tauri/Cargo.toml --bin folio -- save <url>`、`list`、`verify <id>`。

## 链接排队与 Agent 归档

粘贴链接后点 **加入归档队列**，软件只存链接，不访问原站、不调用提取器。配置好本机 Agent 后，由它定时从队列取出链接、打开原页并核对，完成离线归档后才标记成功。没有 Agent 时会一直等待；遇到验证或无法核实时保留原因，可在处理后点「重新排队」。原有「导入浏览器保存的页面」仍可用。

本机 Agent 接口及验证要求见[待归档队列](docs/archive-queue.md)。

## 开发

需要 Rust 1.90+、Node 22+。macOS 还需要 Xcode；Linux 需要 Tauri / WebKitGTK 系统开发依赖。iOS / Android 打包分别需要 Apple 签名工具链、Android SDK/NDK。

```sh
npm ci
npm test
npm run tauri -- dev
npm run tauri -- build
```

首次 Rust 构建需要下载 crates。Linux 依赖请参见 [Tauri 前置条件](https://v2.tauri.app/start/prerequisites/)。

## 隐私与边界

- 公开源码只包含程序；下载内容写入当前用户的数据目录 `tech.stardream.starfolio/library/`，Unix 上目录权限为 0700；Windows 使用用户目录继承的权限。不要把该目录、浏览器导出文件或真实帖子内容提交到 GitHub。
- 归档不是加密保险库。磁盘、系统账号、云同步及备份的安全由使用者负责。
- 显式运行 CLI `folio save` 的抓取仅请求标准 HTTP(S) 公网地址、拒绝重定向到私网或从 HTTPS 降级；不跟随系统代理。单页最多 3000 楼，单个图片最多 12 MiB、每页 200 MiB。被站点验证拦截时，使用浏览器导出的公开可见内容或 HTML 导入，不自动破解验证。
- 网页可能改变、缺楼、热链失效或禁止复制；自动提取器无法识别每个站点结构。保存时会展示缺失项。
- 删除站点广告不改变原站，也不改变外链内容。

## AI 如何参与

默认先探测 **本机 Ollama**（固定 `127.0.0.1:11434`）及 `qwen2.5:3b`，不使用云模型或中转。陌生 HTML 站点由模型按 DOM 候选块编号判断正文、评论与噪声，不让模型重写原文；结构明确的 Discourse 优先使用真实楼层与作者字段。保存前再分批用模型检查正文/评论摘录，异常只标记，不删楼。正文 SHA-256、图片完整性、来源和缺失记录由代码检查。摘要式复核不是逐字事实核查。

要启用本地 AI，请先在 Ollama 中准备 `qwen2.5:3b`（`ollama pull qwen2.5:3b`），用 `ollama list` 确认，再导入归档。星藏不自动下载模型，也不接受云模型。

模型不可用、输出无效或超预算时仍保留可读快照，书架和「AI 复核」面板会说明状态，不伪称 AI 通过。本机准备好 Ollama 和模型后，可对已有快照选「AI 复核 → 重新复核」，或运行 `folio review <id>`，不会重新访问原站。此操作复核已保存的摘录，不会补回原本没抓到的内容。

对于可在浏览器正常阅读、自动下载却受限的论坛，打开源码中的 `tools/bookmark.html`，把导出按钮拖进书签栏；在主楼点击书签后正常向下阅读，再点计数按钮导出。星藏书架中选「导入浏览器保存的页面」。这只读取已经显示的楼层，不读取登录凭据、不自动翻页。普通文章可导入 UTF-8 HTML；不跟随本地文件路径，推荐含内嵌图片的单文件 HTML。

移动平台需准备相应工具链。Android 首次运行 `npm run tauri -- android init`，然后 `npm run tauri -- android build`；iOS 工程位于 `src-tauri/gen/apple`，用 `npm run tauri -- ios build`。构建检查与真机验证是两回事，请以具体平台 CI 结果为准。

## 关于与更新

右上角的 GitHub 图标打开项目仓库。「关于」显示当前版本。启用了签名更新的桌面安装包可以手动检查，也可勾选「启动时自动检查更新」（默认关闭）。找到新版后会先提示，点击「安装并重启」才下载、验证签名及签名中的版本并安装。更新不发送归档内容，也不修改书架；未配置更新的试用包和移动版不提供应用内更新。打包及隔离测试见[更新维护说明](docs/updates.md)。

## 整理书架和迁移旧备份（0.2）

- 阅读页工具栏的「打开原文」在系统浏览器打开归档来源，滚到评论区也能点。没有来源链接的归档不显示此按钮，离线阅读不会自动访问原站。
- 在书架组合使用分类、域名、作者、AI 标签和搜索；可以只看「暂无 AI 标签」。作者按当前筛选下归档的主帖篇数从多到少排列，不计评论；换域名会清除已选作者。在阅读页点「更改分类」可自定义，留空恢复原分类；不会改写原文。
- 书架每页显示 20 篇，列表底部可翻页；切换筛选会回到第一页，从阅读页返回会保留当前页。作者篇数按匹配结果统计，不受翻页影响。见[分页验收](docs/shelf-pagination.md)。
- 在书架或阅读页点「阅读语言」，可以跟随系统、中文优先或原文优先。缺少译文时显示原文；已有英文归档可离线补存中文译文，不覆盖原文。见[双语归档规则](docs/reading-language.md)。
- 在书架或阅读页点「显示时区」，可跟随系统（默认）、固定为北京时间 / UTC，或选择其他时区。归档时间与发帖时间分别显示；缺少时区的源数据照原样显示。设置仅影响应用显示，不修改原始记录或独立离线 HTML。
- 每次新归档会用同一个本机模型根据标题、主文摘录生成最多 5 个主题标签。没有模型或输出不合格时标签留空，已有标签不被清除；以后点「重新复核」可补标，不接触云端。来源栏目是分类，不冒充 AI 标签。
- X：支持旧博客的 v3 单帖 JSON；主文必须是原文，旧档已标明的译文回复原样保留并提示。从 `tools/x-bookmark.html` 安装可选书签，在自己有权阅读的公开原帖上手动记录可见回复 / 图片并导出 JSON。不抓私信、视频、未知回复树或未显示内容；遇验证即停。通过帖子 ID 去重，区分作者回复和普通可见回复；历史互动数字只指备份当时。
- `folio import-collection <资料集目录>` 从目录内的 `catalog.json` 增量导入，按 SHA-256 校验记录与本地图像，未附图片标为缺失，不回源。中断后重跑即可，资料不变不重复入库。单个 JSON 也可从书架导入。命令行可用 `STARFOLIO_LIBRARY` 指定独立测试书架；应用始终使用自己的用户数据目录。
- 软件不会发布归档。另建的个人公开资料集应只包含主动选择公开的文章，不能拿私人书架整个推送。

### 一键复制图文（0.2.1）

打开归档，点 **复制图文**，再到目标编辑器粘贴。默认只复制标题、正文和其中的本地配图，按原顺序排列；需要楼层署名、评论和评论配图时先勾选 **含评论**。不用先滚动加载图片，不会回访原站。缺图会留下文字提示。只接收纯文本的输入框会得到文字和图片说明；部分富文本应用也会自行过滤图片。

点击复制才会写入系统剪贴板，软件不读取剪贴板。系统的剪贴板历史或跨设备同步可能保留副本。单次图文上限为 64 MiB；Android 系统剪贴板容量更小，超限会明确提示，不会悄悄只复制文字。

### 离线作者头像（0.2.2）

阅读页在主帖和评论的署名旁显示本地头像。X、Discourse 和有明确作者标记的网页可以保存头像；拿不到或身份对不上就留空，不用正文配图代替。相同作者复用本地记录，相同图片只存一份。头像记录的是采集日期，不代表发帖时的样貌；「复制图文」不带署名旁的头像。

已有书架可用 `folio import-avatars <头像目录>` 从本地资料集单独补录，不抓正文或评论，不重写原始图文；再次运行会跳过已有记录。对于有权整理的旧 X 公开资料集，可运行 `python3 tools/backfill-x-avatars.py <资料集目录> <私有进度目录>`；它只读取未核实作者的公开主页与头像，缓存进度，遇到访问限制会停止。进度目录必须在公开资料集之外。私人站点的头像和索引同样留在私人书架，不会自动发布。


### X 长文、引用原帖与独立图片

备份网页先在 Ego Lite 打开原文。X 书签区分普通推文和 X 长文；长文封面放在开头，正文中的图按原位置存放。使用浏览器正常加载的媒体文件和 `folio import-collection` 可离线导入，不回访源站。旧长文出现明确的缺失封面标记时，用 `folio restore-x-cover <归档 ID> <核实的封面 URL> <本地图片>` 原位补录，无需重导入。

有证据的 X 引用保存在 `quoteUrl`，阅读页显示「引用原帖」。如果卡片没有显示链接，正常打开引用卡、核对作者与原帖链接后，再为主帖备份补上；不把引用当作回复，也不猜链接。V2EX 结构化浏览器备份可用 `starfolio.v2ex.v1` 记录原帖及可见回复，通过资料集与图片一并导入。

单独收藏图片时，在 macOS 可用 `swift tools/image-ocr.swift <图像>` 本机识字。核对识别结果，准备含 `title`、`text`、`description`、`tags` 的 JSON（真实来源可另填 `source_url`），再运行 `folio import-image <图像> <元数据 JSON>`。`text` 只放图中可辨识文字；无字时用 `description` 描述画面。原图留在本机，以内容去重；书架可按识别文字、描述和标签搜索。导入不会联网生成标题或标签。
